- У нас будет горизонтальное масштабирование, т.к. при вертикальном мы упремся в физические лимиты.
- Наше приложение будет развернуто в нескольких зонах безопасности с независимые кластерами kubernetes в каждой площадке. Единый растянутый кластер нам не подходит из-за высоких требований к доступности, а единый кластер предлагает и единую точку отказа, мы не сможем переключится на работающий кластер в случае падения приложения.
- Репликация между базами будет master-master. Шардирование не будет, т.к. объем данных ещё не столь большой.
- Мы будем использовать active-active failover strategy, т.е. у нас будут активны сразу несколько кластеров, а трафик между ними мы будем перенаправлять используя GSLB. Выбор этой стратегии продиктован высокими требованиями к доступности 99,9%.
- Будет health-check со стороны GSLB. Если health-check проваливается, то на кластер не будет поступать трафик.
- Для соответствия RPO ≤ 15 мин, будет бэкап бд в s3 каждые 10 минут.
- Статику будем отдавать через CDN, чтобы пользователи из разных регионов получали её с одинаково быстрой скоростью.
