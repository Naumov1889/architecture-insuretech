## Проблемы и риски REST API взаимодействия сервиса ins-product-aggregator
- Каждый сервис обращающийся к ins-product-aggregator заставляет его делать одни и те же запросы. 
- Запросы долгие и синхронные. Увеличение кол-ва запросов, увеличивает время ответа ins-product-aggregator.
- Если одна страховая не отвечает, то она задерживает весь запрос к ins-product-aggregator.
- Если одна страховая не ответила, то обращающиеся сервисы не получать информацию от страховой до следующего запоса к ins-product-aggregator.

## Решение
Обновлённая схема в виде [drawio xml](./InsureTech_C4_сontainer-diagram.drawio.xml). <br>
Тоже самое в виде картинки:
![](./InsureTech_C4_сontainer-diagram.drawio.svg)

- ins-product-aggregator сам будет инициировать запросы к страховым раз в 15 минут. Для этого добавим очередь задач. Запрос к каждой страховой будет отдельный, с ретраями.
- В ins-product-aggregator добавим базу данных для хранения данных от страховых.
- Оставим текущие rest api endpoint'ы для совместимости, пока другие сервисы не перейдут на работу с очередью сообщений. Но переделаем. Теперь ins-product-aggregator не будет делать запросы к страховым, а будет отдавать данные из бд.
- Применим паттерн Transactional Outbox. После получения данных из страховой, ins-product-aggregator будет писать в таблицу Product и в рамкох этой же транзакции будет писать в таблицу Outbox. После чего отдельный процесс будет публиковать сообщения в очередь сообщений: Polling Publisher периодически опрашивает таблицу или Transaction Log Tailing посредством CDC-инструментов (Change data capture) подписывается на изменения в этой таблице.
- Все желающие сервисы (core-app и ins-comp-settlement) подписываются на сообщения от ins-product-aggregator и асинхронно обрабатывают их, обновляя свои локальные бд.
<br><br>
- Избавимся от REST API запросов от ins-comp-settlement к core-app раз в сутки. Так как в REST API сложно гарантировать, что ins-comp-settlement получит данные, т.к. core-app может быть недоступен. Заменим текущее синхронное REST API взаимодействие на асинхронное взаимодействие Event Sourcing: при изменении данных по страховке core-app публикует в очередь сообщений, ins-comp-settlement подписывается на очередь, читает и обрабатывает сообщение.
